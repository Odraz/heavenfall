**Status: prepared** (2026-10-12, spec revision 9). Prepared against branch `rogue` at the R0 records commit `2d0be8d`, whose code is identical to `main` `fa9e3f5`. Dependency: R0, awaiting your review ([r00-report.md](r00-report.md)). No unresolved defects carry over. Build it with the implementation prompt in [development-workflow.md](development-workflow.md) (`NN = 01`).

## Playable outcome

Every run builds a new Pearly Gates floor of 10–11 rooms from its seed.
1. The party starts in the Breach and sees each door's sigil.
2. Walking into an idle combat room starts a 20 s countdown; the room seals and the waves come.
3. The room clears, the doors open, and the party picks the next door.
4. Cleared rooms trickle a few leashed Blessed when revisited.
5. The minimap and the hold-M full map show what's known.
6. The boss room is reached only through the Confessional and holds the inherited Gatekeeper as a labeled fixture.

Co-op and bots work as today.

**Before:** one fixed sequence of arenas. **After:** a different floor every run, and a route choice at every cleared room.

**Fixture limits** (labeled in the game where a player would notice):

| Where | What's missing in R1 | When it arrives |
|---|---|---|
| The Pardoner's stall, the Confessional | Empty shells | Shop R3, Advocate R4 |
| Combat rooms | No props, pickups, Dominion or fire. Prop sockets, hazard rects and elite waves are parsed and validated but inactive. | R2 |
| Clear rewards, door reward plates | None | R3 |
| Key room, map-reliquary room, bells | Chosen by the generator, but do nothing | R6 |
| The boss | The inherited fight. Its death ends the run as today (no Stair). | R7 |
| XP and halos | Kills and clears give none | R2 halos, R3 XP |
| Countdown holds (shopping, overlays) | Inert | R3 and R4 |
| Pilgrim's Return | Clicking a room on the map does nothing | R6 |
| Crest | Arrives at today's 10/s per spawn point over 10 s, not the 6 s and 20/s rule | R2 |
| Unsafe spawns | No warned floor fallback | R2 |
| Unreachable enemies | Relocated without a beam | R2 |

The old fixed dungeon stays reachable as a development fixture.

## The R1 room pool

The 10 combat templates that need no Dominion and no Refiner's Fire. In **pool order**, which the weighted picks iterate:

1. `pg-c-1x1-ranged-01`, `pg-c-1x1-ranged-02`, `pg-c-1x1-ranged-03`
2. `pg-c-1x1-flyers-01`, `pg-c-1x1-flyers-02`, `pg-c-1x1-flyers-03`
3. `pg-c-2x1-horde-01`, `pg-c-2x1-ranged-01`, `pg-c-2x1-flyers-01`
4. `pg-c-2x2-horde-flyers-01`

**Specials:** `pg-s-breach-01`, `pg-s-pardoner-01`, `pg-s-confessional-01`, `pg-b-gate-01`.

**Coverage check.** A floor has at most 7 normal combat rooms. Exactly one is 2×2 and at most two are 2×1/1×2, so it needs at most six 1×1 templates, and six exist. The single 2×2 template has bands 2–3, which matches the rule that a 2×2 is never band 1. The pool can therefore always fill a legal floor without repeating a template. Adding R2's ten templates changes pool order and thus floors for a given seed; that is a `RULES_VERSION` bump.

**R1 fallback floor** ([rooms.md](rooms.md) §5 with substitutions for templates outside the pool, recorded as a fixture limit):

| Room | Spec template | R1 template |
|---|---|---|
| R2 (1×2) | `pg-c-2x1-horde-hazard-01` | `pg-c-2x1-horde-01` |
| R6 | `pg-c-1x1-elite-01` | `pg-c-1x1-flyers-02` |
| R7 (map reliquary) | `pg-c-1x1-hazard-02` | `pg-c-1x1-ranged-02` |
| R8 (Reliquary) | `pg-c-1x1-ranged-hazard-01` | `pg-c-1x1-ranged-03` |

R1, R3 and R4 keep their spec templates. Every band still fits its template, and no template repeats. Orientation is the first valid one in canonical order, so R2 takes the first valid 1×2 orientation.

## Implementation contracts

### Map data (`src/data/dungeons/types.ts`, `src/sim/map.ts`)

```ts
export type RoomKind = 'breach' | 'pardoner' | 'confessional' | 'combat' | 'boss';
export type Cell = [number, number];
export type Quad = [Cell, Cell, Cell, Cell];
export interface RoomLeaf { socket: number; to: number; cells: Quad }  // own D cells; to = far room, -1 = outside every room
export interface RoomEntry { socket: number; cells: Quad }            // 3 cells inward, across the socket
export interface RoomDef {
  id: string; name: string; kind: RoomKind;
  rect: { x0: number; y0: number; x1: number; y1: number };          // inclusive
  leaves: RoomLeaf[];                                                // socket ascending
  entry: RoomEntry[];                                                // one per used socket, socket ascending
  waves: WaveDef[];                                                  // counts at 4 players; [] for non-combat and boss
  boss: boolean;                                                     // === (kind === 'boss')
  shape?: '1x1' | '2x1' | '1x2' | '2x2';                             // absent in fixtures
  band?: 1 | 2 | 3; focus?: Focus; secondary?: Focus;
  templateId?: string; orientation?: number;                         // 0–3 rotations clockwise, 4–7 mirrored then rotated
  hazards?: Array<{ rect: Rect; hazard: string }>;                   // stamped, inactive until R2
  points?: { reward?: Cell; pedestals?: Cell[]; advocate?: Cell;
             addSpawns?: { gate: Cell[]; field: Cell[] }; watchers?: Cell[] };
  chorister?: number[];                                              // preferred spawn indices (spawnAffinity), used in R2
}
export interface GateDef { facing: 'N' | 'E' | 'S' | 'W'; plane: number; u0: number; u1: number; uCenter: number }
export interface DungeonDef { id; name; heights: string[]; markers: string[]; rooms: RoomDef[];
                              decor?: Record<string, DecorId>; gate?: GateDef; viewMask?: string[] }
```

- **Fixed dungeons keep their `ArenaDef` source.** `adaptFixture(def): DungeonDef` (`src/data/dungeons/fixture.ts`) converts each arena:
  - `kind` is `'boss'` if `boss`, else `'combat'`;
  - `entry = [{socket: 0, cells: entryCells}]`;
  - `leaves`: the entry `doors` with `to = i − 1`, or `-1` for arena 0, and the `exitDoors` with `to = i + 1`;
  - the gate becomes `{facing: 'W', plane: x, u0: y0, u1: y1, uCenter: yCenter}`.
  
  `getDungeon` returns the adapted def, so callers see only rooms.
- **`GameMap` changes:**
  - `arenas` → `rooms`;
  - `doorArena` → `doorRoom`;
  - `arenaSpawnPoints` → `roomSpawnPoints`;
  - `arenaSquadPoints` → `roomSquadPoints`, fixture only;
  - new `roomOf: Uint8Array` (room index inside each rect, 255 elsewhere);
  - new `hazard: Uint8Array` (0 none, 1 `refiners-fire`), stamped from `hazards`;
  - new `viewMask: Uint8Array | null` (1 = an open edge may form; `null` = unrestricted, as today).
  
  `loadMap` keeps every current `MapError`, with "arena" read as "room".
- **The leaf rule replaces `doorsClosed`/`arenaPhaseOf`.** `leafOpen(r, leaf, activeRoom, activePhase, clearedMask)` lives in `src/sim/map.ts`. A leaf is open iff all of:
  - room `r` is not (`r === activeRoom && activePhase === COMBAT`);
  - and either `cleared(r)` or `cleared(leaf.to)`, where `to = -1` counts as cleared.
  
  `applyLeaves(map, header)` sets `solid`/`top` for every leaf. Host and client call the same function with the snapshot header's values. With the fixture's `to` values this reproduces today's door behaviour.
- **`validateLevel(map, markers, mode: 'fixture' | 'floor')`** (`validate.ts`).
  - **Shared checks**, unchanged except that "arena" reads "room": the jump perch, sealed rooms with leaves closed, all border cells walls, `WALL_TOP`, unreachable large decor, no overlapping rects, every `x` inside a room.
  - **`'fixture'` mode** keeps today's per-arena rules: 6 `x`, 4 entry cells, `S` outside every rect, only the last arena may be the boss.
  - **`'floor'` mode** applies §14.2 (a)–(e):
    - (a) at least 6 `x` only in `combat` rooms, each enemy-reachable;
    - (b) every `entry[k]` has 4 non-door floor cells inside the rect, one per used socket;
    - (c) the 4 `S` cells are inside the Breach and no other room;
    - (d) exactly one `boss` room, with `B` inside it on the dais; its add markers, entries and Watcher anchors are reachable; the dais is exempt from ground reach and is not a player perch;
    - (e) the gate's post cells lie on the boss room's gate wall.
- **Zones** (`heights.ts`): room `i` is zone `i` (its rect floor plus its leaf cells). Vestibule floor forms its own small zones. `computeHeights` drops open-edge candidates where `viewMask` is 0 **before** the facing loop.
- **The Gate** (`src/render/gate.ts` and the gate code in `sim.ts`): one transform maps the canonical W-facing layout to `facing`. It covers the layout, terrain skip, posts, collision and hit boxes, and light sampling, and samples the floor from the adjacent interior cell (§14.2).

**The pool** (`src/data/rooms/`):
- `types.ts` holds `RoomTemplate` exactly as rooms.md §2.
- `notation.ts` holds `expandRoom(text): RoomTemplate`. It expands rooms.md §2.1's block notation, including the stair formula, the glyph tables, the `walls` lines, the boss's gate/field split at cell x ≤ 5, and pedestal and Watcher order. Errors it rejects:

- room budget = `base(shape)` (400 / 700 / 2000) × the band factor (0.85 / 1.0 / 1.15);
- `count = round(rest × mix ÷ TP)`, at least 1 where the mix is nonzero.

### Room lifecycle (`src/sim/sim.ts`)

**`RoomState`** replaces `ArenaState`. It keeps the existing wave, queue and director fields and adds:
- `knowledge` (0 undiscovered, 1 discovered, 2 visited)
- `entrySocket`
- `cancelTicks`
- `refills` (3)
- `lastHumanTick`
- `trickleAt`
- `holdUsed` (inert)

Phases keep the `PHASE_*` values in `protocol.ts`. `activeRoom` and `activePhase` are stored explicitly; `arenaStatus()` goes.

**Dispatch by `kind`** happens in `checkRoomStarts`, which replaces `checkArenaStarts`:

| Kind | On first visit | Seal and fight | Clear |
|---|---|---|---|
| `breach` | Cleared and visited from tick 0 | — | — |
| `pardoner`, `confessional` | `idle → cleared` | — | — |
| `combat` | Countdown starts (rules below) | Waves through the per-room director | Rules 8 below |
| `boss` | Countdown starts | `placeBoss` | Only by victory, which ends the run as today |

An empty ordinary-combat wave list fails content validation. The `isCombatArena` wave-length test goes; the bench arena keeps its special case.

**`P` and solo.**
- `P` = connected in-game humans + 0.5 × bots, at least 1. `SimPlayer` gains `bot: boolean`, from `hello.bot`.
- `partyMultiplier(P)` is the linear interpolation through (1, 0.4), (2, 0.6), (3, 0.8), (4, 1.0). Integer values equal today's `MULT10`.
- `scaleCount(n, P) = Math.ceil(n × mult(P) − 1e-9)`.
- `solo` = exactly one human and no bots. It replaces the `singleplayer` flag in `regenerate` and in `bossMultiplier`.

**Regeneration** (§4.3 *Exact passive sustain*):
- the solo breath only while the active combat room's director is in relax;
- the 1.5%/s baseline only in a solo boss fight;
- nothing in idle, countdown, cleared rooms or vestibules.

Today's idle regeneration goes.

**The countdown** (§4.3 rules 1, 2, 4, 5, 6). Constants:
- `COUNTDOWN` 20 s (was 60);
- `COUNTDOWN_ALL_IN` 3 s (was 5);
- `COUNTDOWN_CANCEL` 3 s.

Rules:
1. **Start.** A living human's feet are in an idle `combat`/`boss` rect, no room is active, and victory or defeat hasn't latched. `entrySocket` is the used socket whose entry-cell centroid is nearest that human (ties: lower socket).
2. **Ticking.** The timer advances only while at least ⌈H ÷ 2⌉ living connected humans are in the rect or its vestibules. A vestibule is any cell with `roomOf = 255` inside the rect grown by 4 cells.
3. **Everyone in.** When every living connected human is inside the rect and none stands in a vestibule, the timer drops to `min(value, 3 s)`.
4. **Cancel.** No living human in the rect for 3 s in a row, or `H = 0`, returns the room to `idle`; it stays visited.
5. **Seal.** At 0:
   - living players (bots included) outside the rect or in a vestibule, and souls outside it, go to `entry[entrySocket].cells[index]` via the existing `teleport` correction;
   - `P` and `mult(P)` are fixed;
   - the director is `new Director(waves.length, cap, solo)` with `cap = min(1500, max over waves of (size[i] + floor(0.3 × size[i−1])))`;
   - the fields are invalidated.

**Waves and spawning** (§4.3 rule 7, R1 part):
- `SPAWN_FAR_DIST` is 10 m in a generated 1×1 and 15 m otherwise (2×1, 2×2, fixtures), then the existing 8 m fallback.
- New `SPAWN_MIN_DIST = 3`: never place within 3 m of a living player. If no marker passes, the batch stays queued and counts as unfinished.
- The crest uses today's `SPAWN_RATE`.

**Clear** (§4.3 rule 8):
- every connected living player heals `0.3 × maxHp`, replacing the full heal at `sim.ts:1109`;
- the dead respawn at 50% HP on `entry[entrySocket]`;
- `roomState` is emitted.

**Anti-softlock** (rule 9), checked every 5 s for enemies of the sealed room:
1. An enemy is unreachable when every living player's ground field (air for Cherubs) is `UNREACHABLE` at its cell.
2. After 10 s unreachable, move it to the farthest player-reachable authored marker of its room, keeping HP and state. The move is instant in R1.
3. After a further 10 s with no legal marker, remove it with no kill credit and log `diagnostic: unreachable enemy removed`.

After the last wave is fully placed, up to 10 enemies that have neither moved 1 m nor taken damage for 20 s get the same handling.

**Discovery.** A room's knowledge becomes `visited` when a living human's feet enter it. Every room sharing a vestibule with it becomes `discovered`. Each change increments `stateRevision` and emits `roomState`. The Breach and its neighbours start visited and discovered.

**Trickle** (§4.8):
- **Trigger:** a living human enters a cleared `combat` room where no human stood for the last 10 s, with `refills > 0` and no active room. After 3 s, if a human is still inside, spawn `floor(min(12, 4 + 2P))` Blessed.
- **Placement:** on the room's `x` markers not visible from any living player's eye (LOS to the marker centre at 1 m); else the farthest from the party. `refills` decrements.
- **Leash:** the enemy record gains `home: Uint8Array` (255 none) and `leashed: Uint8Array`. Every enemy displacement refuses a cell whose `roomOf ≠ home` and clamps to the last legal cell. That covers `moveEnemy`, separation (`separate`/`tryDisplace`), the Fallen's knockback, the Binder's pull, Falling Star's landing and Discord's gust.
- **Behaviour:** trickle enemies target only players inside `home` and stand idle otherwise.
- **Fade:** they are removed without credit after 10 s with no living player in `home`. None appear after the boss's death.

**Flow fields** (§14.5). `FlowField.compute(tc, tr, clamp?)` treats cells outside `clamp` (the room rect grown by 4 cells) as solid. Fields are computed only for players standing in a room (`roomOf` of the feet) that has living enemies. The air field only while flyers are alive. The cadence is unchanged.

**Joining** (§12.2, first-time join only):
- during combat, as a soul on the active room's entry cells;
- otherwise next to the lowest-id living player.

### Map, HUD and presentation (`src/client/`)

- **`rooms.ts` (client room model).**
  - Phases come from the snapshot header.
  - Knowledge and `entrySocket` come from `roomState` events and `floorSync`.
  - Geometry (slots, kind, focus, marks) comes from the locally generated `Floor`.
- **`mapIcons.ts`.** One `Path2D` glyph per icon in §5.2's table, drawn white with a dark outline. Every icon differs in shape, and the same glyphs serve the map and the door sigils.
- **`mapView.ts`, the minimap.** A fixed 200 × 200 px canvas plate at top-right, 1 slot = 28 px, drawn from the floor's slot coordinates. It draws:
  - the §5.2 fills and outlines (red pulsing at 1 Hz for countdown and combat);
  - the 6 px gaps and connectors between rooms;
  - your own arrow and teammates' dots.
  
  *Enemies remaining* moves under it. In fixtures the plate reads `No map in the fixture`.
- **`mapView.ts`, the full map.** Shown while **M** is held: a 588 × 588 px plate (1 slot = 84 px), the view dimmed 40%, a legend column and player names.
  - The mouse moves a map cursor; LMB and RMB send no fire bits.
  - It is hidden while chat or Pause is open.
  - Clicking a room does nothing (Pilgrim's Return arrives in R6).
  - `input.ts` adds keydown/keyup for `KeyM`.
- **Door sigils.** A 1.2 m canvas-texture quad above each leaf, on the face toward its owner room, shows the glyph of the room the leaf opens into (`leaf.to`). Built by the renderer's door code next to `scene.setDoorsClosed`.
- **HUD messages:**
  - `Another room is sealing`: computed locally when your feet are in an idle combat room while another room is active;
  - `Waiting for the party (n/H)`: from the header's hold byte;
  - `The doors are sealed` and `Room cleared`: on `roomState` transitions of combat rooms.
- **Loading:** `Building the Pearly Gates…` while generating.
- **Bots** (`src/client/bot.ts`):
  - countdown: go to the active room's `entry[entrySocket]` cells;
  - otherwise: follow the host's living player, or the lowest-id living human;
  - single-player autopilot (`?bot=1`): walk to the entry of the nearest discovered, uncleared, non-boss room adjacent to a cleared room (BFS over open leaves, ties lower index); with none left, the boss room.
- **Music:** by shape, per default 2.

### Protocol and run identity (`src/net/`)

- **`src/net/version.ts`:**
  - `PROTOCOL_VERSION = 2` (the inherited format is 1);
  - `RULES_VERSION = 1`;
  - `newRunIdentity()`: `{runId, seed, simSeed}` from `crypto.getRandomValues`. `runId` is 32 lowercase hex characters; the seeds are u32.
- **Build fingerprint** (`vite.config.ts`). `__BUILD_VERSION__` becomes `${pkg.version}+${gitShort}.p${PROTOCOL_VERSION}.r${RULES_VERSION}.${srcHash}`.
  - `srcHash` = the first 12 hex characters of SHA-256 over every file under `src/` except `*.test.ts` and `testutil/`. Files are taken in sorted path order; each contributes its path, a NUL, its bytes with CRLF normalized to LF, and a NUL.
  - Two dirty builds at the same commit therefore differ, but Windows and Linux checkouts of the same commit agree.
  - The dev server computes it at startup, so restart it after edits before a multiplayer test.
  - `hello.version` carries it. `Lobby.join` already rejects a mismatch before anything else, which is before generation.
- **Control messages** (`messages.ts`):
  - `hello` gains `bot: boolean`.
  - `welcome` and `lobby` replace `dungeonId` with `heaven: number` and `fixture: string | null`.
  - `start`: `{ type: 'start'; runId: string; heaven: 1; floor: 1; seed: number; simSeed: number; edicts: 0; progressionEnabled: false; fixture: string | null; players: Array<{ id; name; classId; bot }> }`. `Lobby.start()` draws the identity; `maybeGo` and joiners reuse it, and the worker no longer draws a seed at `go`.
  - `event`: `{ type: 'event'; runId; tick; revision; event }`. Clients drop events of another run.
  - `GameEvent`: `arenaStarted` and `arenaCleared` are replaced by `roomState { room, phase, knowledge, entrySocket }`.
  - New H→one `floorSync { runId, tick, revision, rooms: Array<{ phase, knowledge, entrySocket, refills }> }`. It is sent right after `go` and before any other event to that client. It is under 1 KB, so R1 sends it as one message; chunked catch-up is R3.
- **Worker messages** (`workerMessages.ts`). `start` carries the `start` fields above instead of `dungeonId`/`seed`/`singleplayer`, plus `startRoom?` replacing `startArena?`.
- **Input, 49 bytes** (`INPUT_BYTES = 49`). The host checks, in this order:
  1. the exact length;
  2. the run id;
  3. that the floats are finite and the reserved flag bits are zero.
  
  Only then does it touch the sequence history. Local transport uses the same bytes.

  | Offset | Type | Field |
  |---|---|---|
  | 0 | u32 | `seq` |
  | 4, 8, 12 | f32 | `x`, `y`, `z` |
  | 16, 20 | f32 | `yaw`, `pitch` |
  | 24 | u8 | `fire` |
  | 25, 26 | u8 | `qPresses`, `ePresses` |
  | 27 | u8 | `allyTargetId` |
  | 28 | u16 | `lastTeleportId` |
  | 30 | 16 B | `runId` |
  | 46, 47 | u8 | `item1Presses`, `item2Presses` (0 until R3) |
  | 48 | u8 | flags: bit 0 `mapHeld`, bit 1 `qHeld`, bit 2 `eHeld`; other bits must be 0 |

- **Snapshot header, 61 bytes** (`HEADER_BYTES = 61`). It is repeated in every part, followed by the players (32 B each, unchanged), then this part's enemies (8 B, unchanged until R4), then projectiles (9 B).

  | Offset | Type | Field |
  |---|---|---|
  | 0 | u8 | schema = `PROTOCOL_VERSION` |
  | 1, 2 | u8 | `partIndex`, `partCount` |
  | 3 | u8 | `playerCount` |
  | 4 | 16 B | `runId` |
  | 20 | u32 | `tick` |
  | 24 | u32 | `stateRevision` |
  | 28 | u8 | `activeRoom` (255 = none) |
  | 29 | u8 | `activePhase` |
  | 30 | u16 | `countdown` (tenths of a second) |
  | 32 | u8 | hold: bit 7 waiting; bits 3–5 humans inside; bits 0–2 `H` |
  | 33 | u32 | `clearedMask` (bit *i* = room *i* cleared) |
  | 37 | u16 | `enemiesRemaining` |
  | 39, 43 | u32 | `bossHp`, `bossMaxHp` |
  | 47, 48 | u8 | `bossCast`, `bossCastProgress` |
  | 49, 51, 53 | u16 | totals: enemies, projectiles, pickups (pickups 0 until R2) |
  | 55, 57, 59 | u16 | this part's enemies, projectiles, pickups |

- **Decoding and assembly.** The decoder rejects a wrong schema or a short buffer. The client checks `runId` before the assembler. `SnapshotAssembler.reset(runId)` runs on every new run, and parts of another run are dropped before any state is allocated. Siblings whose totals disagree invalidate their tick. The four-tick/500 ms bound is R2.

## Play checklist (Gate A)

Start a game from the menu (Singleplayer), or `?dev=1&map=rogue&seed=<n>&class=<class>` to repeat a floor. F3 shows the seed.

1. **Solo, two runs** with two different classes on different seeds: walk from the Breach to the boss room, clearing every combat room on the way, and look at the map before each choice.
2. **Co-op** with a friend, or with a bot tab (`?bot=1`), on a third seed: one player scouts into a room and leaves before the countdown ends; then everyone enters. Leave one player outside at the seal.
3. **Backtrack** into a cleared room and wait 3 s for the trickle.

Watch for:
- doors that never open;
- a room that won't seal or clear;
- seeing into another room that is fighting;
- a straggler left outside after the seal;
- the map disagreeing with what you've seen.
